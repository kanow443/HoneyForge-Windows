# HoneyForge: операции в интерфейсе v2

Проверено по текущему frontend и опубликованным API 10 октября 2026 года. Для браузерных операций ниже базовый путь API — **/api/v1**. Машинная интеграция использует отдельный **/integration/v1**. UUID в адресах — идентификатор записи базы, а не отображаемый номер или upstream-ID сенсора.

## Доступ

| Роль в панели | Просмотр | Расследования, закрытые данные, дела, экспорт и файлы | Профили, ловушки и ограничения | Хосты, пользователи и интеграции |
| --- | --- | --- | --- | --- |
| Наблюдатель (viewer) | Да | Нет | Нет | Нет |
| Аналитик (analyst) | Да | Да | Нет | Нет |
| Оператор (operator) | Да | Да | Да | Нет |
| Администратор (admin) | Да | Да | Да | Да |

Роль видна рядом с именем в верхней панели. Недоступные действия скрыты или отключены с пояснением; прямое открытие административного адреса показывает «Действие недоступно». Сервер самостоятельно проверяет права и может вернуть 403. Истечение/отзыв сессии требует повторного входа. Скрытие кнопки не заменяет серверную проверку.

## Создание и публикация профиля

1. Откройте **Профили → Создать профиль**. В конструкторе три раздела: **Сервис**, **Файлы**, **Ресурсы**. Справа — локальный предпросмотр.
2. В разделе «Сервис» заполните **Название профиля**, выберите **Протокол** и **Образ сервиса**, измените **Название сервиса** и **Имя хоста**. Название профиля — до 100 символов; «Описание» в **Дополнительных настройках** — до 500. Образ подставляет поддерживаемые параметры и синтетические файлы; он не имитирует сетевой OS fingerprint.
3. Настройте один из протоколов в таблице ниже. Технические параметры раскрываются через **Дополнительные настройки**.
4. Нажмите **Опубликовать** вверху. Откроется проверка протокола, уровня, схемы, порта, настроек записи, файлов и ресурсов. Затем **Опубликовать версию**.

| Действие | API | Результат в UI | Ошибки и права |
| --- | --- | --- | --- |
| Опубликовать новый профиль | POST /profiles | Серверный профиль и опубликованная версия; это ещё не работающая ловушка | operator/admin; локальная и серверная валидация, ошибка сохраняет форму |
| Опубликовать следующую версию существующего профиля | POST /profiles/{id}/versions | Новая неизменяемая конфигурация; предыдущие версии остаются в истории | operator/admin; архивный профиль не публикуется |
| Перейти к настройкам v2 из старого черновика | Локальное изменение до публикации | Появляются порт, учётные записи, запись и связь с центром; исходная опубликованная v1 сохраняется | Явная кнопка **Перейти к настройкам v2**; автоматического изменения истории нет |
| Развернуть опубликованную версию | **Развернуть** на профиле открывает /traps/new?profile={id}; последующая отправка формы POST /deployments | Задание с состоянием сервера и подтверждением агента | operator/admin; нужны доступный хост, подходящий порт и неархивный профиль; публикация не равна запуску |

Новые черновики используют схему v2. Изменение текущего профиля не обновляет уже запущенные ловушки: для применения другой версии требуется отдельное повторное развёртывание. Предпросмотр — локальная модель конфигурации; он не создаёт событий и не доказывает сетевую доступность.

### Протоколы

| Выбор «Протокол» | Где и что менять | Предпросмотр и границы |
| --- | --- | --- |
| **TCP-баннер · Low** | Основные поля **Баннер TCP** и **Ответ на TCP-запрос**; каждая строка до 256 символов, баннер обязателен, ответ может быть пустым; рекомендуемый порт по умолчанию 2223 | Баннер и простой ответ TCP; без входа, команд и файлов. Раздел «Файлы» недоступен |
| **HTTP-портал** | В дополнительных настройках **Страница входа**: «Консоль активов» / «Файловое хранилище», **Баннер HTTP-сервера**; порт по умолчанию 18080 | Medium HTTP: поддерживаемый шаблон страницы и файловый список. Произвольный HTML/ZIP и реальная авторизация в preview не поддерживаются |
| **SSH-среда** | В дополнительных настройках **Баннер SSH**, **Загрузка файлов**: «Запрещена» по умолчанию либо «Лабораторный образец»; порт по умолчанию 2222 | Medium Cowrie, эмулируемая среда. Preview поддерживает hostname, whoami, ls, cat; это не shell реальной ОС и не High |

Для «Лабораторного образца» UI показывает только допустимую команду **wget http://downloads.honeyforge.test:18090/sample.txt**. Она относится к развёрнутой SSH-ловушке; предпросмотр ничего не запускает. Доступ к произвольным интернет-файлам не заявляется.

### Дополнительные настройки v2

Все параметры сохраняются в конфигурации через публикацию; выбор значения не применяет его к работающему агенту.

| Поле/раскрываемая группа | Правила | Что означает |
| --- | --- | --- |
| **Рекомендуемый порт** | Целое 1024–65535 | Подстановка при развёртывании; не открывает порт самостоятельно |
| **Учётные записи-приманки** → «Логин приманки N», «Пароль приманки N», «Добавить учётную запись-приманку», «Убрать» | 1–8 записей для HTTP/SSH; логины уникальные, 1–64 символа латиницы/цифр/подчёркивания/точки/дефиса; пароли 8–128 символов латиницы/цифр/подчёркивания/точки/@/дефиса | Только синтетические данные для приманки. Это не доступ в HoneyForge |
| **Запись взаимодействия** → «Сохранять введённые учётные данные» | Флажок; для HTTP/SSH | Сбор закрытых данных отделён от доступа к обычным событиям |
| **Лимит HTTP payload, байт** | 0–8192; 0 отключает запись тела | Ограничение сохраняемых байт; возможна усечённая запись |
| **Лимит вывода SSH, байт** | 16384–1048576 на канал | Квота вывода, а не гарантия полноты при ошибке сенсора |
| **Связь с центром** → «Интервал связи, секунд» | 1–60 | Интервал запросов агента |
| **Разброс интервала** | 0,1–0,5; 0,2 = 20% | Разброс запросов, не доказательство скрытности или доступности |

Ошибки конкретного поля показываются у поля; проблемная группа раскрывается. Перед публикацией настройки перечислены в проверке. Синтетические пароли присутствуют в конфигурации профиля и её JSON; закрытые перехваченные значения в обычный JSON профиля не входят.

### Файлы и редактор

**Файлы → выбрать документ в дереве**. Поле **Путь файла** допускает поддерживаемые пути /home/, /var/www/ или /opt/decoy/ без обхода каталогов. **Добавить файл** — до 12 документов; содержимое — до 8192 символов на файл. CodeMirror показывает строки, подсвечивает JSON, поддерживает поиск/замену; **Поиск в файле** и расширение рабочей области доступны в инструментах.

Изменения сразу видны в локальном preview. Переключение документов сохраняет отдельную историю отмены и положение курсора; развёрнутый режим даёт больше места редактору. Черновик сохраняется в этой вкладке, а не как серверная публикация. Удаление файла меняет черновик; итог попадает в API только при публикации. Для Low файлов нет. На узком экране панели перестраиваются; desktop-файловый режим отдаёт больше ширины редактору.

## Сведения, архив, восстановление, удаление

Откройте **Профили → нужный профиль**. Работа со сведениями отделена от изменения опубликованной конфигурации.

| Где нажать | API | Что показывает UI | Ошибки и права |
| --- | --- | --- | --- |
| **Изменить сведения** → «Название профиля», «Описание профиля» → **Изменить сведения** | POST /profiles/{id}/metadata | Новые сведения; конфигурации версий и их хеши сохраняются | operator/admin; название обязательно, ≤100, описание ≤500; серверная ошибка остаётся в окне |
| **В архив** → **Архивировать профиль** | POST /profiles/{id}/archive | Дата архива; недоступны новая публикация, новое/повторное развёртывание | operator/admin; версии и уже работающие ловушки сохраняются; остановка существующей ловушки остаётся доступной |
| В реестре «Состояние профиля» → **В архиве**; открыть профиль → **Восстановить** → **Восстановить профиль** | POST /profiles/{id}/restore | Профиль снова доступен для публикации и развёртывания | operator/admin; восстановление не перезапускает ловушки |
| **Другие действия → Удалить профиль → Удалить профиль** | POST /profiles/{id}/delete | После успешного OkayView — возврат к реестру | operator/admin; действие необратимо; 409 при любой истории развёртывания, включая остановленные ловушки. Для такого профиля используется архив |

## Закрытые данные события

В журнале откройте событие; в плеере нажмите **Исходное событие**. Если сервер сообщил private_capture_available, доступна кнопка **Закрытые данные события** для analyst/operator/admin.

1. Нажатие кнопки только открывает подтверждение: запрос за значениями ещё не отправляется.
2. Установите **Подтверждаю раскрытие закрытых данных**, нажмите **Раскрыть данные**. Отправляется **POST /events/{database-UUID}/private-capture**; раскрытие фиксируется в журнале оператора.
3. UI показывает «Введённый логин», «Введённый пароль» (маскирован по умолчанию), **Показать пароль / Скрыть пароль**. HTTP payload показан как Base64, не выполняется; размер и усечение отображаются отдельно.
4. **Закрыть и очистить**, Escape, смена события или потеря роли очищают локальное состояние. Поздний ответ для закрытого/другого события не раскрывается.

Закрытые значения не помещаются в Query/Mutation cache, local/session storage, обычный экспорт, печать или клиентские логи. Это не удаление записи с сервера и не очистка внешнего буфера обмена/скриншотов. Viewer получает пояснение вместо кнопки, сервер возвращает 403 при прямом запросе. Отсутствие записи, истёкший срок хранения, недоступный ключ расшифровки и ошибка запроса показываются как ошибка, а не как пустой успешный ответ. UUID ответа сверяется с выбранным событием.

## Дела, закрепление и конфликт версий

**Дела → открыть дело** либо вкладка сессии **Дело и контекст**. Изменение заметки и статуса сохраняется только через **Сохранить изменения**: **POST /cases/{id}**, передаётся текущая revision.

| Действие | API | Что увидеть | Ошибки и права |
| --- | --- | --- | --- |
| **Закрепить доказательства** | POST /cases/{id}/retention, revision и pinned=true | Новая revision, «Доказательства закреплены»; связанные данные удерживаются | analyst/operator/admin; серверная ошибка не заменяется успехом; одновременное сохранение блокируется |
| **Снять закрепление** → подтверждение **Снять закрепление доказательств** → **Снять закрепление** | Та же операция с pinned=false | Возврат к обычному сроку хранения | analyst/operator/admin; после снятия уже истёкшие данные могут быть удалены при следующей очистке, закрепление их не восстановит |
| При несовпадающей revision — **Загрузить актуальную версию** | Использует свежие данные дела из GET /cases | Актуальная revision, статус и заметка заменяют локальный вариант | 409 требует разрешить конфликт; автоматической перезаписи заметки нет; загрузка актуального варианта заменяет несохранённый текст |

Закрепление/снятие сохраняют несохранённую заметку в UI, но не публикуют её вместо отдельной кнопки сохранения. Viewer не может менять/закреплять дело. Пока запрос выполняется, повтор/конкурирующее сохранение недоступны. Закрепление не является резервной копией удалённых доказательств.

## Хранилище и файлы доказательств

**Хранилище → Обновить** читает **GET /storage**. Таблица показывает фактические квоты, зарезервированное место, закреплённые данные и retention capacity из ответа. Это вместимость хранения, не подтверждение живого агента или активных ловушек. Ошибка чтения отображается явно; недоступные значения не подменяются нулями.

На ловушке или во вкладке сессии **Доказательства** доступны статусы: получение байт, доступен, срок истёк, удаляется. Для receiving/purging/expired скачивание недоступно. Available-файл скачивается только роли investigate: UI отдельно проверяет размер и SHA-256 полученных байт, ошибка целостности прерывает результат. Совпавший хеш не означает проверку на вредоносность. PCAP относится ко всей ловушке и содержит шифрованный SSH; команды нужно смотреть в плеере сессии.

## Интеграции и одноразовый секрет

Раздел **Интеграции** доступен только администратору. **GET /integration-tokens** возвращает метаданные, не секрет/хеш ключа; список показывает последние 200 записей. Viewer, analyst и operator не получают экран управления даже по прямой ссылке; серверные операции требуют admin.

| Где нажать | API | Результат в UI | Ошибки/ограничения |
| --- | --- | --- | --- |
| **Создать ключ** → «Название», «Ловушка», «Срок действия, дней» → **Создать ключ** | POST /integration-tokens | Окно **Сохраните ключ** с одноразовым секретом, по умолчанию скрытым | По умолчанию только чтение, 30 дней; срок 1–365; «Все ловушки» допустимо для чтения |
| Установить **Разрешить ответные действия** | Поля create включают response_enabled и одну deployment_id | Явная привязка к выбранной ловушке | Требуется одна ловушка; нет разрешения на произвольную машинную/сетевую изоляцию |
| **Показать ключ**, **Копировать ключ**, закрыть окно/Escape | Нового API чтения секрета нет | Секрет только в локальном состоянии окна, закрытие очищает его | Копирование явное; внешний clipboard не очищается автоматически. Потерянный секрет восстановить нельзя |
| В строке ключа **Отозвать** → **Отозвать ключ** | POST /integration-tokens/{id}/revoke | Отозванный ключ; для его ограничений запрошена отмена | Снятие ограничения подтверждает агент отдельно. Закрытая SSH-сессия не восстанавливается |

Если соединение оборвалось во время создания, сначала проверьте список: ключ мог быть создан, хотя секрет не получен. Список не позволяет восстановить секрет; ненужный ключ можно отозвать. Наличие ключа не означает подключённый внешний SIEM или работающий receiver.

### Машинный API из подсказки «Как подключить получатель событий»

**GET /integration/v1/events**, Authorization: Bearer с выданным ключом. after берётся из next_cursor, limit=1–500; has_more требует продолжить чтение, reset_required — сбросить курсор. Формат фиксированный **honeyforge-ecs-events-v1**, поднабор ECS 8.0; переключателя native/ecs нет.

Ключ с ответными действиями может отправить **POST /integration/v1/source-blocks**: event_id из database event.id, ttl_seconds=60–300, reason, обязательный Idempotency-Key длиной 8–100. Повтор того же действия использует тот же ключ. **202** означает запрос. **GET /integration/v1/source-blocks/{id}** показывает отдельные подтверждения ограничения подключений и закрытия SSH. Ограничение действует в одной выбранной ловушке, не изолирует машину целиком. Отзыв ключа запрашивает отмену его активных ограничений; агентский ACK проверяется отдельно.
