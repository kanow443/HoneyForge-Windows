# План продукта HoneyForge

Цель — показать управляемую систему ловушек от настройки до расследования. Самая сильная демонстрация: оператор создаёт профиль, запускает его на другом хосте, выполняет контролируемое подключение и сразу видит, что произошло. После обрыва связи накопленные события появляются без дублей.

План рассчитан на одного человека, который поручает реализацию ИИ и принимает результаты по проверяемым критериям. Дедлайн неизвестен: порядок определяется зависимостями и готовностью, а не обещанием уложиться в произвольное число часов.

## Что известно из задания

Источник — [карточка задания](source/honeyforge-brief.jpg), предоставленная 9 октября 2026 года. Это описание продукта; действия, перечисленные в нём, не являются разрешением развёртывать сервисы в чужой инфраструктуре. Стенд реализации — собственные учебные хосты.

В карточке указаны централизованная конфигурация профилей, удалённое развёртывание ловушек разных уровней взаимодействия, сбор входящей активности и исходящей телеметрии в реальном времени, хранение и анализ данных. FastAPI, Python, Node.js, PostgreSQL и HTML/CSS/JS перечислены как технологии с пометкой «и др.». Это основание предложить стек, но не доказательство обязательности всех перечисленных технологий.

| ID | Требование | Реализация в основном объёме | Как доказать на защите |
| --- | --- | --- | --- |
| R01 | Единый центр управления | Авторизованная панель, хосты, профили, ловушки, события | Пройти весь сценарий без переключения между отдельными инструментами |
| R02 | Конфигурация профилей | Шаблон, имя хоста, параметры сервиса, фиктивные ресурсы, версия | Изменить профиль; показать новую версию и сохранение старой |
| R03 | Удалённое развёртывание | Агент на отдельной Linux VM, задания deploy и stop | Показать отдельный адрес, agent ID и фактический контейнер на VM |
| R04 | Различные уровни взаимодействия | Низкий: HTTP-приманка; средний: эмулируемая SSH-среда Cowrie | Сравнить HTTP-ответ и SSH-сессию с командами |
| R05 | Входящая активность в реальном времени | HTTP-запросы, SSH-подключения, авторизация, команды | Связать реальное подключение с событием и сессией в UI |
| R06 | Исходящая телеметрия | Heartbeat, ресурсы, очередь, ошибки, сведения о попытках исходящих соединений | Показать состояние агента и проверяемое событие ограничения сети |
| R07 | Хранение | PostgreSQL, локальная очередь агента, миграции | Перезапустить API; открыть сохранённую сессию |
| R08 | Анализ | Фильтры, временная шкала, версии правил, объяснимые признаки | Открыть сработавшее правило и события, на которых оно основано |

Реальная передача сетевых пакетов, команды эмулятора, сетевой отказ и метрики агента — разные источники. UI отмечает источник и степень наблюдения. Термин «вся активность» ограничивается поддерживаемыми сервисами и документированной политикой сбора; полный сетевой захват не заявляется без отдельной реализации.

В карточке не уточнено, обязательны ли все три уровня взаимодействия. Основной объём покрывает два разных уровня. Если жюри требует высокий уровень, отдельная виртуальная машина с настоящей ОС становится обязательным этапом; эмуляцию нельзя переименовать в высокий уровень.

## Продуктовые сценарии

1. Оператор выбирает шаблон HTTP или SSH, задаёт легенду и сохраняет версию профиля.
2. Оператор выбирает доступный хост и свободный порт, видит итоговую конфигурацию и запускает ловушку.
3. Панель показывает этапы применения конфигурации, фактический статус и причину ошибки, если запуск не удался.
4. Учебный клиент подключается к ловушке. Панель получает событие с временем, источником и привязкой к ловушке.
5. Оператор открывает сессию, смотрит последовательность действий и объяснение аналитического правила.
6. Оператор останавливает ловушку; история остаётся доступной.
7. При недоступности API агент продолжает собирать события в пределах квоты. После восстановления связи доставляет их повторяемо и без повторного учёта.

## Основной объём P0

- Одна организация и одна роль оператора с входом в панель. Проверка авторизации применяется ко всем API, SSE и экспорту.
- Регистрация одного удалённого агента и поддержка нескольких записей хостов. Демо обязательно использует отдельную VM.
- Два адаптера: собственная HTTP-приманка и Cowrie в режиме эмуляции SSH.
- Профили с неизменяемыми опубликованными версиями и проверкой допустимых полей.
- Задания развёртывания и остановки, ошибки, heartbeat, согласование желаемого и фактического состояния.
- Локальная очередь, повторная доставка, дедупликация и восстановление потока в браузере.
- Обзор, хосты, профили, ловушки, события и просмотр сессии.
- Объяснимые правила, экспорт JSON, журнал действий оператора.
- Проверка изоляции, сбоя связи, перезапуска и согласованности статусов.
- Документы решений, доказательства и короткое видео рабочего сценария.

В основном объёме нужен один убедительный сценарий для каждого адаптера. Десять шаблонов с одинаковой логикой ценности не добавляют.

## Расширения после P0

| Приоритет | Функция | Когда добавлять |
| --- | --- | --- |
| P1 | Откат к ранее опубликованной версии | После надёжных deploy и stop; откат оформляется новым заданием |
| P1 | Второй настоящий удалённый хост | После доказательства изоляции и доставки на первом |
| P1 | High interaction через Cowrie proxy и выделенную одноразовую VM | Если этого требует оценка или остаётся время на сетевые проверки и очистку |
| P1 | Отчёт с выборкой событий и параметрами сбора | После работающего экспорта JSON |
| P2 | Краткое резюме сессии по шаблону | Без нейросетей; на основе правил и ссылок на события |
| P2 | SIEM, SSO, GeoIP и дополнительные протоколы | После законченного основного сценария |

На старте достаточно Compose, PostgreSQL и одного API. Kubernetes, Kafka, Elasticsearch, визуальный редактор произвольных схем и магазин плагинов добавляются только при конкретном требовании, которое нельзя закрыть текущими компонентами.

## Реалистичность ловушки

Реалистичность достигается согласованной легендой: баннер сервиса, имя хоста, структура фиктивных файлов и содержимое не противоречат друг другу. HTTP-шаблон похож на правдоподобную страницу служебного входа с фиктивным названием сервиса. SSH-шаблон предлагает согласованную эмулируемую файловую структуру. Все данные синтетические.

Проверка реалистичности: два профиля дают различимые ответы; изменение имени отражается в поддерживаемых ответах; фиктивный файл существует и читается в эмуляторе; неподдерживаемое поведение явно описано. Проект не обещает, что опытный специалист никогда не распознает ловушку.

## Критерии готовности

Ниже цели приёмки, а не измеренные характеристики.

| Проверка | Целевой результат |
| --- | --- |
| Сквозной HTTP-сценарий | Профиль из панели → удалённый запуск → запрос → событие → stop |
| Сквозной SSH-сценарий | Вход в эмулятор → две команды → сохранённая последовательность в UI |
| Задержка | p95 от регистрации события агентом до появления в UI ≤ 2 с на учебном стенде при 10 событиях/с |
| Сбой связи | После 60 с недоступности API все тестовые события в пределах квоты доставлены и учтены один раз |
| Повтор | Повторная отправка 100 тех же event ID не меняет число сохранённых событий |
| Перезапуск | API и агент восстанавливают очередь и состояние после принудительного завершения |
| Ошибка развёртывания | Занятый порт даёт понятный отказ, без статуса Running |
| IP источника | Адрес клиента на другой машине совпадает с наблюдением сервиса; трансляция адреса отмечена |
| Сеть | Ловушка не создаёт новые соединения с API, БД, агентом, LAN и внешним контрольным адресом; ответ на разрешённый входящий запрос работает |
| Авторизация | Неавторизованный клиент не получает данные, SSE и экспорт |
| Недоверенный контент | HTML, ANSI и формулы из логов не исполняются в панели или экспорте |
| Сохранность | После перезапуска доступны профили, задания и прошлые сессии |
| Защита | Демо дважды подряд проходит от исходного состояния; видео и схема готовы |

Задержку измерять по синхронизированным часам стенда и браузера, отдельно показывать время источника и время приёма. Прогоны сохранять с объёмом данных, конфигурацией и точным способом измерения. Если цель не достигнута, в защите использовать фактическую величину.
