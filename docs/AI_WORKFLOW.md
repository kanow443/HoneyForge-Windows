# Работа с ИИ над HoneyForge

Один человек управляет последовательной реализацией. ИИ получает ограниченную задачу, реализует её, проверяет результат и обновляет документы. Человек принимает поведение по сценарию и доказательствам, а не по длине ответа или объёму написанного кода.

## Цикл каждой задачи

1. Прочитать README, соответствующий раздел архитектуры, ADR и конкретную T-задачу. Проверить текущее состояние файлов и окружения.
2. Сформулировать короткий план изменения и будущую проверку. Учитывать уже выполненные этапы и не переписывать их без причины.
3. Выполнить одну задачу. Если найден необходимый технический prerequisite, сделать минимальное дополнение и записать причину.
4. Проверить нужное свойство: контракт, БД, реальный runtime, браузер или сеть. Использовать моки только там, где они не подменяют доказательство свойства.
5. Сохранить результат в `docs/evidence/Txx/`: конфигурация, безопасный лог, expected/actual, скриншот/видео при необходимости. Не сохранять ключи, токены и настоящие пароли.
6. Обновить WORKLOG и фактический статус задачи. Если решение изменилось, обновить ADR с причиной. Не ставить «готово» при непроведённой обязательной проверке.
7. Зафиксировать связное изменение в истории проекта, когда Git уже создан. Отчёт человеку: что работает, почему так, чем проверено, какие ограничения остались.

Каждое существенное действие фиксируется отдельно: изменение контракта, выбор библиотеки, миграция, исправление ошибки, применение настройки VM, проверка и решение о сокращении объёма. Повтор чтения одного файла и каждое нажатие клавиши записывать не требуется; точные команды проверки и фактические результаты обязательны.

## Готовое задание для начала реализации

```text
Изучи README.md, docs/PRODUCT_PLAN.md, docs/ARCHITECTURE.md,
docs/DELIVERY_PLAN.md, docs/DECISIONS.md и docs/WORKLOG.md.
Выполни T01 для HoneyForge. Сохрани существующие документы.
Сначала проверь окружение и выбери совместимые закреплённые версии.
Подготовь каркас управления, интерфейса и агента, схемы v1,
локальный запуск и проверку результата по приёмке T01.
Не объявляй удалённое развёртывание, сетевую изоляцию и доставку
реализованными до их фактической проверки в следующих задачах.
Сохрани evidence T01 и запись действий в WORKLOG.
Если обнаружишь препятствие, продолжи независимую часть и укажи,
каких конкретно данных или возможностей окружения не хватает.
```

## Задание для следующего этапа

```text
Продолжи HoneyForge с задачи Txx из docs/DELIVERY_PLAN.md.
Изучи фактические предыдущие результаты в WORKLOG и evidence.
Выполни зависимые изменения и все критерии приёмки этой задачи.
Запиши существенные действия: что, зачем, где, проверка, результат.
Обнови ADR при изменении архитектурного решения.
Верни краткий отчёт с ссылками на доказательства и реальными ограничениями.
```

Вместо Txx подставляется одна конкретная следующая задача. Дополнительные агенты не нужны для основного плана; при необходимости независимые задачи можно разделить явно, сохраняя одного владельца контракта и итоговой проверки.

## Проверки по смыслу

| Что изменили | Подходящая проверка |
| --- | --- |
| Модель/правило | Положительный и отрицательный пример, граница окна/порога |
| SQL и транзакция | Интеграционный тест с PostgreSQL, конкурентность при необходимости |
| Доставка | Сбой до/после commit/ACK и сверка event IDs |
| Deploy | Настоящий runtime, readiness, повтор, stop и занятый порт |
| Сеть | Реальные соединения из нужного сегмента, IPv4/IPv6, source IP |
| UI | Работающий браузер, реальные API, состояния ошибок и offline |
| Оформление документа | Проверка ссылок, терминов и соответствия фактическому состоянию |

Не писать тест только для повторения собственного алгоритма. Проверять обещанное поведение и опасные границы. Сборка не доказывает запуск; mock агента не доказывает remote deployment; зелёный health не доказывает работающую ловушку.

## Пакет доказательств

```text
docs/evidence/Txx/
  result.md           среда, шаги, expected/actual, ограничения
  checks.log          команды и окончательные результаты без секретов
  screenshots/        наблюдаемые состояния, если есть UI
  samples/            очищенные events, exports, конфигурация
```

Это будущий формат. Папка evidence пока не содержит результатов работы приложения. Скриншоты Mobbin являются референсами и не используются как доказательство реализованного UI.
