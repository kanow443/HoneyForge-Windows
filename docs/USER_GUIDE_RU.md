## 1. Что делает приложение

HoneyForge — единая панель создания и управления сервисами-приманками. Оператор задаёт легенду сервиса, публикует конфигурацию, выбирает удалённый сенсор и запускает ловушку. Посетитель взаимодействует с HTTP-порталом или SSH-эмулятором; агент сохраняет наблюдения и передаёт их в API. Панель показывает события, сессии, объяснения правил, карту подключений и состояние инфраструктуры.

Рабочая цепочка: **профиль → опубликованная версия → развёртывание → наблюдение → сессия → объяснение правила → ответное действие → дело → отчёт**.

В продукте нет нейросети, внешнего AI API, генерации ответов моделью или автоматических выводов о личности атакующего. SSH отвечает через Cowrie, HTTP — через собственный сенсор. Правила детерминированы: имеют идентификатор, версию, объяснение и ссылки на события.

Low — отдельный TCP-адаптер с баннером и фиксированным ответом, без авторизации и команд. HTTP и SSH/Cowrie — Medium: форма входа, эмулируемая оболочка и синтетические файлы.

## 2. Компоненты и основные понятия

| Понятие | Что означает | Где увидеть |
| --- | --- | --- |
| Оператор | Пользователь панели управления | Имя в верхней панели, журнал оператора |
| Хост / сенсор | Отдельная Linux-машина с агентом и Docker | «Хосты» |
| Агент | Забирает задания, управляет контейнерами, собирает и доставляет данные | Heartbeat, очередь и метрики хоста |
| Профиль | Именованная легенда одного сервиса или набора из 2–8 сервисов | «Профили» |
| Версия профиля | Неизменяемая опубликованная конфигурация: `v1`, `v2` и далее | Карточка профиля и сессии |
| Группа развёртываний | Несколько сервисов одной версии профиля на одном сенсоре, с отдельными портами и общими действиями | «Многосервисные группы» в «Развёртываниях» |
| Развёртывание / ловушка | Конкретное применение версии на хосте и порту | «Развёртывания» |
| Endpoint | Адрес сервиса-приманки, например `192.168.139.142:2222` | Карточка ловушки |
| Задание | Асинхронная операция агента: запуск или остановка | «Применение конфигурации» |
| Revision | Номер желаемой конфигурации/действия; устаревший ответ не заменяет новый | Карточка ловушки, ограничение, дело |
| Runtime generation | Идентификатор поколения запуска; отделяет старый контейнер от нового | «Точное состояние», технические данные |
| Событие | Сохранённое наблюдение с ID, временем, источником и payload | «События», плеер |
| Сессия | Связанные взаимодействия одного подключения/посетителя с ловушкой | Плеер сессии |
| Provenance | Откуда пришли данные: `cowrie`, `http-sensor`, сетевой сборщик и т. п. | Детали события и отчёт |
| Evidence ID | ID записи, на которую ссылается объяснение правила | Плеер, отчёт |
| Срабатывание | Результат конкретного правила, а не произвольная оценка модели | «Срабатывания правил», плеер |
| Outbox | Локальная долговечная очередь событий агента | «В очереди» у хоста |
| SSE | Поток уведомлений от API к браузеру; после уведомления панель обновляет данные | LIVE, индикатор связи |
| Ограничение источника | Временное правило, блокирующее новые подключения IPv4-источника к одной ловушке | «Ответные действия» |
| ACK | Подтверждение агента, что конкретная ревизия правила применена или снята | Состояние ограничения |
| Дело | Набор сессий, заметка оператора и состояние расследования | «Дела» |
| SHA-256 | Контрольная сумма содержимого отчёта/экспорта | Конец отчёта, JSON |

**Два разных IP:** IP хоста — куда подключаться для демонстрации; IP источника — откуда пришло наблюдаемое подключение. IP не определяет человека. Показанная команда `uname -a` описывает легенду SSH-приманки, а не ОС посетителя.

## 3. Локальный стенд, доступ и запуск

### 3.1. Адреса этого ноутбука

| Компонент | Адрес | Что должно открыться |
| --- | --- | --- |

| Готовность API | `http://127.0.0.1:8100/health/ready` | Ответ с состоянием готовности |
| PostgreSQL | `127.0.0.1:55432` | Это адрес базы, не веб-страница |

Это адреса текущего стенда. На другом компьютере адрес VM может отличаться. Актуальные подготовленные ловушки записаны в `.runtime/demo.json`. Старые остановленные ловушки и отозванные хосты могут оставаться в базе: это сохранённая история, а не неисправность новых ловушек.

### 3.2. Где взять пароль панели

1. Открой Finder.
2. Нажми `Cmd+Shift+G`.
3. Вставь `/Users/admin/Documents/GitHub/hack/.runtime` и нажми Enter.
4. Открой `access.txt` и используй записанные там имя и пароль.

Пароль оператора отличается от учебного пароля SSH-приманки. `.runtime/access.txt`, `.env` и индивидуальный ключ агента — приватные файлы, они не входят в Git. В этом руководстве секреты оператора не опубликованы.

### 3.3. Если стенд уже установлен

Открой OrbStack и проверь, что работает VM `honeyforge-sensor` и контейнер PostgreSQL. Для запуска управляющей части открой «Терминал». Каждую длительно работающую команду запускай в отдельной вкладке; вкладки API и панели оставь открытыми.

**Вкладка 1 — база и API:**

```sh
cd /Users/admin/Documents/GitHub/hack
docker compose up -d postgres
uv run alembic upgrade head
uv run uvicorn honeyforge.api.main:app --host 127.0.0.1 --port 8100 --reload --reload-dir src --timeout-graceful-shutdown 2
```

Если API уже использует 8100, вторую копию запускать не нужно. Открой `/health/ready` и используй работающую.

**Вкладка 2 — панель:**

```sh
cd /Users/admin/Documents/GitHub/hack/apps/web
npm run dev
```

Ожидаемый адрес — 5173. Если сервер предложил другой порт из-за занятого 5173, сначала выясни, не работает ли уже нужная панель: origin и proxy должны соответствовать настройкам стенда.

**Вкладка 3 — подготовка демонстрации, после готовности API:**

```sh
cd /Users/admin/Documents/GitHub/hack
uv run python scripts/prepare-demo.py
```

Скрипт создаёт или повторно использует демонстрационные профили и ловушки Low/HTTP/SSH. Остановленные подготовленные ловушки запускает повторно. Он не очищает историю и не подменяет реальные события. Если сенсор не на связи, сначала восстанови агент.

### 3.4. Первая установка и обновление сенсора

Полная установка описана в [DEPLOYMENT.md](DEPLOYMENT.md). Требуются Docker/Compose, Python 3.12+, `uv`, Node.js/npm и отдельная Linux VM с Docker, iptables и systemd. На текущем macOS используется OrbStack. Для комфортного стенда рекомендованы 16 ГБ RAM и 10–15 ГБ свободного места; это рекомендация, не измеренный минимальный порог.

Порядок: `scripts/setup.sh` → собрать три образа → запустить API и HTTPS management gateway → выгрузить публичный CA → создать изолированные VM → `scripts/provision-lab.py --install` для каждого сенсора → `npm ci` и запуск панели → `scripts/prepare-demo.py`. Точная последовательность с командами находится в DEPLOYMENT.md.

`provision-lab.py` обновляет код, образы и службы сенсора. Новое содержимое образа уже работающая ловушка получит после явного «Применить повторно». При отозванной идентичности используется отдельный `--reenroll`: регистрируется новый хост, старый остаётся отозванным. Для обычного запуска этот флаг не нужен.

Escape или крестик закрывает окно. Это поиск по навигации, а не по базе событий. Выбор действия открывает форму и сам ничего не публикует.

## 5. Вход

**Адрес:** `/login`. **Назначение:** получить операторскую сессию.

| Поле / кнопка | Что вводить / нажимать | Что происходит |
| --- | --- | --- |
| «Имя пользователя» | Имя из `access.txt`; первоначально подставлено `operator` | До 80 символов, обязательное поле |
| «Пароль» | Пароль оператора | Скрытый ввод, обязательное поле, до 200 символов |
| «Войти в панель» | После заполнения | Отправка логина; на время запроса «Входим…» |

После успеха откроется ранее запрошенная защищённая страница или главная. API сверяет хеш пароля, создаёт cookie-сессию и выдаёт CSRF-токен. Cookie HttpOnly: JavaScript не читает секрет сессии. Ошибка входа остаётся возле формы; ограничение частоты входа может требовать подождать. Неверный пароль не создаёт доступ. Истечение сессии возвращает на вход, сохранённая серверная история остаётся.

## 6. Сеть ловушек и карта подключений

**Адрес:** `/`. **Назначение:** понять состояние стенда и быстро открыть интересующее наблюдение.

### 6.1. Общий обзор

| Блок / действие | Что показывает / куда ведёт |
| --- | --- |
| «Развернуть ловушку» справа вверху | Форма нового развёртывания |
| «Работают … из … ловушек» | Число подтверждённых работающих развёртываний и общее число |
| «На связи … из … хостов» | Состояние подключённых сенсоров |
| «За 24 часа» | Количество сохранённых событий за период |
| «Источники» | Уникальные наблюдаемые IP, не число людей |
| «Последний срез» | Время серверного снимка; резервное обновление обзора каждые 15 секунд |
| Карточка/строка ловушки в «Развёртывания» | Открывает её подробную карточку |
| «Все …» у списка | Открывает полный список развёртываний |
| «Расследовать события» | Открывает журнал событий |
| Столбик графика | Подсказка с временем и количеством при наведении; это не кнопка фильтра |
| «Хосты» и карточка хоста | Список хостов или сведения выбранного сенсора |
| «В очереди», «Отброшено агентами» | Последние известные метрики heartbeat; не непрерывный прямой счётчик SQLite |
| Карточка срабатывания правила | Открывает сессию и выделяет правило; при отсутствии сессии открывает события ловушки |

В пустой сети доступны «Подключить хост» и «Создать профиль». График с нулём наблюдений остаётся пустым; искусственный трафик не добавляется.

### 6.2. «Карта подключений»

Схема строится по сохранённым входящим наблюдениям: **источник → ловушка → хост агента**. Это не географическая карта и не результат сканирования всей локальной сети.

| Элемент | Действие | Результат |
| --- | --- | --- |
| «Период» | 6 или 24 часа | API пересчитывает проекцию, выбор узла сбрасывается |
| Узел источника | Нажать IP | Фильтрует схему и таблицу по источнику; повторное нажатие снимает выбор |
| Узел ловушки | Нажать | Фильтрует её связи и сессии |
| Узел хоста | Нажать | Фильтрует ловушки и наблюдения сенсора |
| Линия источник → ловушка | Нажать или Enter при фокусе | Открывает связанную сессию; если её нет — события с фильтрами |
| «Сессии» под схемой | Нажать | Таблица сессий выбранных узлов |
| «Открыть плеер» в сессии | Нажать | Плеер конкретного подключения |
| «Связи» | Нажать | Таблица наблюдаемых пар источник/ловушка |
| IP в таблице связей | Нажать | Выбор этого источника |
| Название ловушки в связях | Нажать | Карточка развёртывания |
| «Плеер» / «События» в связи | Нажать | Разбор доступной сессии или выборки событий |
| «Сбросить выбор» | Нажать | Все доступные узлы и записи снова видны |
| «Все события» | Нажать | Полный журнал |

Красный цвет означает высокую важность сработавшего правила; янтарный импульс — новое сохранённое наблюдение. Цвет не равен доказательству успешного взлома. Первичная загрузка старой истории не изображается новой атакой. Предпочтение reduced motion учитывается стилями интерфейса.

На самой схеме показано до шести узлов каждой группы. Таблица содержит больше доступных связей. Серверная проекция ограничена 100 источниками, 200 связями и 100 сессиями; при усечении появляется предупреждение. Для полного поиска используй журнал событий. Разные блоки главной могут обновляться в разные моменты: часы снимка помогают это понять.

### 6.3. География и сеть источников

На главной раскрой «География источников». В карточке сессии соответствующий блок называется «География и сеть источника» и показывает строки текущей выборки, относящиеся к этому IP.

- В строках «География» и «ASN» показаны фактическая доступность базы, провайдер, возраст и дата сборки. Если сервер сообщает устаревшую базу, появляется «требуется обновление базы».
- На проверенном стенде подключены оригинальные DB-IP City/ASN Lite выпуска 2026-10, сборка 1 октября 2026 года. Возраст меняется со временем; ориентируйся на текущее значение экрана. База города и база ASN — отдельные источники, поэтому проверяй обе строки.
- Ссылка [DB-IP](https://db-ip.com) и указание CC BY 4.0 обеспечивают атрибуцию данных; [условия DB-IP Lite](https://db-ip.com/db/lite.php).
- Таблица содержит наблюдаемые IP из текущей выборки. Для частного или зарезервированного адреса показано «Локальный или зарезервированный адрес», а сеть — «Не определена». Наличие баз не приписывает частному IP город или организацию.
- Отсутствие IP в текущей выборке не означает отсутствие событий. Для поиска используй журнал. География приблизительна и не определяет личность посетителя.

Живые проверки интерфейса 390/1280: [geo-connected-browser.json](evidence/frontend/geo-connected-browser.json). Проверка самих баз и отдельных адресов: [geo-connected.json](evidence/backend/geo-connected.json).

## 7. Хосты

**Адрес:** `/hosts`; выбранный хост — `/hosts?host=<id>`. **Назначение:** управление идентичностями агентов и качеством сбора.

### 7.1. Список и сведения

| Элемент | Действие / смысл |
| --- | --- |
| «Подключить хост» | Открывает выдачу одноразового токена |
| Имя хоста в строке | Открывает панель сведений, сохраняет ID в адресе страницы |
| Статус | «На связи», «С ограничениями», «Не в сети» или «Отозван» |
| Heartbeat | Последнее подтверждённое сообщение агента |
| CPU / RAM | Метрики Linux-сенсора, не ноутбука посетителя |
| Очередь / потери | Число ещё не доставленных и отброшенных событий из heartbeat |
| HTTP / SSH | Объявленные возможности агента; определяют совместимость с профилем |
| Значок «Отозвать …» | Открывает подтверждение отзыва ключа; для уже отозванного недоступен |
| «Закрыть» в сведениях | Убирает выбранную карточку |
| «События этого хоста» | Открывает журнал с фильтром host ID |

В сведениях видны идентификатор, runtime/version, время связи, parser errors, состояние сетевой политики и время отзыва, если есть. `external-firewall` — отчёт агента о внешних правилах изоляции; отдельные ошибки сбора могут перевести хост в состояние «С ограничениями».

### 7.2. Диалог подключения

1. Нажми «Подключить хост».
2. Прочитай требования Linux/Docker и отдельного контура.
3. Нажми «Получить одноразовый токен».
4. Скопируй токен, сохрани его в защищённом файле на сенсоре.
5. Установи код/зависимости и агент на Linux; выполни показанную команду регистрации с доступным для сенсора адресом API.
6. Запусти агент; дождись heartbeat и появления строки в списке.

Токен действует 10 минут и используется один раз. Видны время окончания и оставшиеся минуты. «Копировать» переносит только токен. При истечении «Выпустить новый токен» выдаёт другой. Крестик закрывает окно, но не разворачивает машину и не устанавливает агент. После регистрации сенсор хранит отдельный ключ; одноразовый токен больше не нужен.

### 7.3. Диалог отзыва

«Отозвать доступ хоста?» содержит «Отмена» и «Отозвать доступ». После подтверждения API аннулирует индивидуальный ключ и сохраняет аудит. Старый ключ больше не принимает задания и телеметрию.

**Отзыв не является подтверждённой физической остановкой.** Если агент получает отказ авторизации, он пытается остановить свои ловушки; при отсутствии связи немедленную остановку гарантировать нельзя. Для штатной остановки сначала используй «Остановить» в карточках доступных ловушек. Старую идентичность обратно не включают кнопкой: повторное подключение создаёт новую.

## 9. Конструктор

**Заголовок:** «Конструктор ловушек». Слева настройки, справа интерактивный предпросмотр. **Текущий интерфейс не является мастером «Шаблон → Легенда → Ресурсы → Файлы»:** все настройки доступны через три раздела «Сервис», «Файлы», «Ресурсы».

### 9.1. Общие действия

| Кнопка / элемент | Результат на экране | Сервер |
| --- | --- | --- |
| Стрелка «Вернуться к профилям» | Каталог или исходный профиль | Новая версия не создаётся |
| «Сервис» / «Файлы» / «Ресурсы» | Переключение раздела, введённые значения сохраняются | Запрос публикации не отправляется |
| «Отменить изменение» | Предыдущее состояние черновика | Нет изменения профиля |
| «Повторить изменение» | Возврат отменённого изменения | Нет изменения профиля |
| «Опубликовать» | Проверка полей и окно «Проверьте перед публикацией» | Пока публикации нет |
| Строка «Черновик сохранён в этой вкладке» | Локальный черновик сохранён через 400 мс после изменения | Сервер черновиков не получает |
| «Восстановлен черновик из этой вкладки» | Поднята сохранённая форма после перезагрузки вкладки | Не является новой опубликованной версией |

Черновик хранится в `sessionStorage` этой вкладки. Это не надёжное долговременное резервное копирование между браузерами. Если хранилище недоступно, редактор работает и сообщает, что черновик не сохранён. Черновик старой базовой версии не должен незаметно заменять новую опубликованную конфигурацию.

### 9.2. Раздел «Сервис»

| Поле / действие | Что задаёт | Проверка / особенность |
| --- | --- | --- |
| «Название профиля» | Название в панели | Обязательно, до 100 символов; при создании новой версии существующего профиля недоступно |
| «Протокол» | HTTP-портал, SSH Medium или TCP Low | Для уже существующего профиля зафиксирован; переключение нового меняет протокольную конфигурацию |
| «Образ сервиса» | Готовый набор настроек легенды | «Консоль инфраструктуры», «Архив резервных копий», «Сервер разработки»; это preset, не выбор произвольного Docker image |
| «Название сервиса» | Видимое название/легенда | 1–80 символов обычного текста |
| «Имя хоста» | Hostname легенды | До 63 латинских букв/цифр/точек/дефисов; не создаёт DNS-запись |
| «Дополнительные настройки» | Раскрыть остальные поля | Само раскрытие ничего не публикует |
| «Описание» | Описание профиля в каталоге | До 500 символов; у новой версии существующего профиля недоступно |
| «Страница входа» — HTTP | «Консоль активов» или «Файловое хранилище» | Меняет HTML-шаблон ловушки |
| «Баннер HTTP-сервера» — HTTP | Строка Server | До 64 символов из разрешённого набора |
| «Баннер SSH» — SSH | Объявляемый SSH banner | Формат `SSH-2.0-…`, допустимые символы и ограниченная длина |

Preset может заменить настройки: используй отмену изменения, если выбран не тот образ. Не вводи реальные пароли/секреты организации в легенду и файлы; демонстрационные данные должны быть синтетическими.

### 9.3. Раздел «Файлы»

| Элемент | Действие / результат |
| --- | --- |
| «Добавить файл» | Создаёт пустой файл `/opt/decoy/file-N.txt`, выбирает его в редакторе; максимум 12 файлов |
| «N из 12 файлов» | Показывает количество файлов черновика |
| Папка в дереве | Сворачивает/разворачивает группу путей; файлы не удаляются |
| Имя файла | Выбирает документ для редактирования |
| «Путь файла» | Переименовывает/перемещает путь внутри конфигурации; до 160 символов |
| Редактор содержимого | Ввод текста, номера строк, поиск и подсветка JSON для `.json` |
| Лупа «Поиск в файле» | Открывает панель поиска и замены CodeMirror |
| «Удалить …» / корзина | Удаляет файл из черновика; вернуть можно отменой изменения до публикации |
| «Развернуть редактор» | Увеличивает рабочую область редактирования |
| «Свернуть редактор» / Escape | Возвращает обычную компоновку |
| «JSON» / «Текст», счётчик символов | Тип подсветки и объём; превышение лимита видно рядом |

Допустимы абсолютные пути внутри `/home/`, `/var/www/`, `/opt/decoy/`; запрещены `..`, обратный слеш, нулевой символ и повторяющиеся нормализованные пути. Содержимое — максимум 8192 символа на файл. Здесь путь относится к приманке, не к файлам macOS. HTML внутри содержимого отображается как текст в операторском интерфейсе, а не выполняется.

В панели CodeMirror можно искать совпадения, перейти к следующему/предыдущему, включить учёт регистра/регулярное выражение/целое слово и выполнить замену одного или всех совпадений. Эти действия меняют только выбранный черновик; после поиска проверь текст перед публикацией.

### 9.4. Раздел «Ресурсы»

| Поле | Допустимый диапазон | Что ограничивает |
| --- | --- | --- |
| «Память» | 64–512 MB, целое значение | Память контейнера |
| «Процессор» | 0,1–2 CPU | Docker CPU quota |
| «Процессы» | 32–256 PID, целое значение | Количество процессов контейнера |

Числовое поле и ползунок задают одно значение. По умолчанию 128 MB, 0,5 CPU, 64 PID. Ограничения вступают в силу после публикации и развёртывания этой версии; изменение ползунка не меняет уже работающий контейнер.

### 9.5. Предпросмотр справа

| Элемент | Поведение |
| --- | --- |
| «Сервис» в предпросмотре | Показывает HTTP-форму или пробный SSH-сеанс |
| «Файлы» в предпросмотре | Список синтетических файлов и содержимое выбранного |
| Имя файла в предпросмотре | Открывает текст файла, не запускает реальную ловушку |
| «Сбросить предпросмотр» | Очищает пробную историю/ошибку входа; конфигурацию не стирает |

### 9.6. Публикация

1. Нажми верхнее «Опубликовать».
2. Исправь ошибки, если форма перевела к неверному полю.
3. В «Проверьте перед публикацией» сверяй протокол, сервис, hostname, файлы, ресурсы.
4. При необходимости раскрой «Конфигурация JSON».
5. «Скачать JSON» скачает конфигурацию черновика; это не серверная публикация.
6. «Опубликовать версию» отправит проверенный документ в API; во время запроса — «Публикуем…».
7. После успеха откроется карточка профиля; появится `v1` или следующая версия.

API повторно проверяет схему, сохраняет неизменяемую конфигурацию, вычисляет hash и записывает аудит. Ошибка валидации или сети не считается успехом; она показывается в форме/диалоге. Созданная версия сама по себе не запускает сервис.

### 9.7. Несколько сервисов — схема v3

В конструкторе нового профиля выбери «Несколько сервисов» либо открой `/profiles/new?adapter=bundle`. Слева находятся общие настройки и список сервисов, в центре — выбранный сервис, справа — локальный предпросмотр. На узком экране эти области располагаются друг под другом.

1. Задай название профиля, общее имя хоста и общую легенду. Они применяются ко всем сервисам; описание раскрывается отдельно.
2. Выбери протокол нового сервиса и нажми «Добавить сервис». В профиле должно быть от 2 до 8 сервисов. Поддержаны HTTP, SSH Medium и TCP Low.
3. Выбери сервис в списке. Задай уникальный ключ сервиса и порт 1024–65535. Два сервиса одного профиля не могут занимать один порт. Стрелки меняют порядок; удаление оставляет не менее двух сервисов.
4. Настрой выбранный протокол. «Файлы» и «Ресурсы» относятся к этому сервису; общая легенда остаётся единой. TCP Low не получает оболочку и файловый раздел. Ресурсы запрашиваются отдельно для каждого контейнера, в общей области показана сумма.
5. Переключай сервисы, используй отмену/повтор изменения и предпросмотр. Это работа с черновиком; контейнеры здесь не запускаются.
6. Нажми «Проверить и опубликовать». В окне проверь все ключи, протоколы, порты и ресурсы; затем нажми «Опубликовать профиль».

Схема v3 описывает **формат набора сервисов**. Версии профиля `v1`, `v2` и далее обозначают последовательные публикации; это другая нумерация. Редактирование существующего профиля создаёт новую неизменяемую версию. Старые одиночные схемы v1/v2 продолжают работать. Черновик набора сохраняется в текущей вкладке, с проверкой исходной опубликованной версии.

| «Все состояния» | Ограничивает список: работает, в очереди, применяется, ошибка, неизвестно, останавливается, остановлена |
| Название или стрелка «Открыть …» | Карточка конкретной ловушки |
| «Всего», «работают», «в процессе», «требуют внимания» | Сводные числа состояний; это не кнопки |

Строка содержит протокол/уровень взаимодействия, состояние, адрес, хост, версию, число событий, время подтверждения. Резервное обновление списка — каждые 15 секунд, SSE также обновляет данные.

### 10.2. Новое развёртывание `/traps/new`

| Поле / кнопка | Что выбрать | Что происходит |
| --- | --- | --- |
| «Название ловушки» | До 100 символов, например `Finance demo` | Название конкретного запуска в панели |
| «Профиль» | Опубликованный HTTP/SSH-профиль | Загружаются версии; прежний выбор версии и хоста сбрасывается |
| «Точная версия» | `v1`, `v2` и т. д. | Фиксирует применяемую конфигурацию |
| `Sensor host` | Совместимый хост на связи | Доступны `online`/`degraded` с нужным адаптером |
| «Подключить хост» при отсутствии совместимых | Нажать | Переход к управлению сенсорами |
| «Порт» | Свободный порт 1024–65535 | Проверяется API и агентом; стандартные привилегированные 22/80 здесь не выбираются |
| «Что будет применено» | Проверить справа | Профиль, версия, протокол, хост, endpoint, легенда и ресурсы |
| «Отмена» / «← Ловушки» | Нажать | Возврат в список |
| «Развернуть ловушку» | Нажать после заполнения | API создаёт развёртывание и задание; открывается его карточка |

Кнопка недоступна без обязательных данных. Повтор того же тела запроса в этой форме использует один ключ идемпотентности: сетевой повтор не должен создать вторую ловушку. Изменённые параметры получают новый ключ.

API фиксирует желаемый запуск, агент забирает задание, получает образ, создаёт контейнер, запускает сервис и проверяет доступность. До фактического результата статус не должен быть «Работает». Занятый порт покажет конфликт/ошибку, а не автоматически завершит чужой процесс.

### 10.3. Карточка `/traps/<id>`

| Кнопка / ссылка | Результат |
| --- | --- |
| «← Ловушки» | Список развёртываний |
| «Остановить» | Окно подтверждения остановки |
| Название профиля / `vN` | Просмотр применённой версии |
| Имя хоста | Сведения сенсора |
| «Развёртывание» | Переход к блоку runtime внутри страницы |
| «События» | Журнал с фильтром этой ловушки |
| «Сессии» | Прокрутка к связанным сессиям |
| Заголовок задания | Раскрывает этапы и ошибку конкретной попытки |
| «Версия профиля» в «Повторное развёртывание» | Выбор конфигурации для следующего запуска |
| «Применить повторно» | Новый revision/generation и задание применения; старые события сохраняются |
| «Разобрать сессию» | Плеер выбранной сессии |
| «Заблокировать источник» в ограничениях | Диалог из раздела 13 |

«Точное состояние» содержит желаемое и наблюдаемое состояния, время подтверждения, ресурсы, image digest и runtime generation. В «Идентификаторах» — deployment ID, profile version ID, время создания. Это данные для воспроизведения/разбора, а не редактируемые поля.

Этапы задания: проверка конфигурации → получение образа → создание контейнера → запуск → проверка готовности → сервис готов. Видна попытка выполнения: при потере агента задание может получить новую аренду. Устаревший результат не должен заменить текущую ревизию.

**Остановка:** «Остановить» → «Остановить ловушку?» → «Остановить ловушку». «Отмена» закрывает окно. После отправки ожидается «Останавливается», после подтверждения — «Остановлена». Профиль, версии, сессии, события остаются. Для повторного запуска используй «Применить повторно». При `unknown` остановка не считается подтверждённой только потому, что кнопка была нажата.

### 10.4. Многосервисные группы

В «Развёртываниях» раскрой «Многосервисные группы» и выбери «Развернуть группу». Кнопка запуска выбранной версии набора в карточке профиля также открывает форму `/groups/new`.

1. Введи название группы и выбери опубликованную версию многосервисного профиля.
2. Выбери хост: в списке доступны только сенсоры на связи, поддерживающие **все** протоколы группы. 
3. Проверь порт каждого сервиса. Можно переопределить порты именно для этого развёртывания. Повторения и известные занятые порты блокируют запрос; окончательную доступность проверяет API и агент.
4. Нажми «Проверить развёртывание», прочитай итоговый список сервисов/портов и подтверди «Развернуть группу».
5. В карточке `/groups/<id>` следи за общим состоянием и состоянием **каждого** сервиса. «Работает» у группы появляется только после подтверждения всех сервисов. Разные состояния, ошибка и неизвестность показываются отдельно; неизвестность не означает остановку.

У каждого сервиса есть переход к карточке ловушки, событиям и доказательствам. Они сохраняют отдельные сессии и историю. 

**Остановить:** нажми «Остановить группу», проверь список и подтверди действие в диалоге. Агент останавливает сервисы отдельно; итоговая остановка требует подтверждения каждого. История сохраняется.

**Применить новую версию:** опубликуй изменения профиля, в карточке группы выбери «Совместимая версия группы», нажми «Повторно развернуть группу» и подтверди «Применить версию к группе». Список содержит только версии с теми же ключами и адаптерами. Группа сохраняет действующие порты, даже если рекомендуемые порты в новой версии изменены. Для другого состава или протоколов создай новую группу.

Отдельный сервис группы допускает аварийную остановку. Его повторное развёртывание выполняется через всю группу — ссылка в карточке направляет к ней. Архивный профиль нужно восстановить перед повторным развёртыванием.

Проверенный сценарий с реальными HTTP/Cowrie/TCP: [multiservice-browser.json](evidence/frontend/multiservice-browser.json).

**Адрес:** `/events`. **Назначение:** поиск отдельных наблюдений и переход к расследованию.

| Элемент | Что делает |

Фильтры отражаются в URL — адресом можно поделиться с другим авторизованным оператором. «Событий нет» может означать пустую выборку, а не отсутствие телеметрии во всей системе. Сначала проверь ловушку, период, источник, тип и паузу.

| Элемент | Что означает / действие |

## 12. Сессия и живой плеер

**Адрес:** `/sessions/<id>`. Вход: карта → «Открыть плеер», карточка ловушки → «Разобрать сессию», событие → «Разобрать сессию», карточка правила или дело.

### 12.1. Шапка и разделы

| Элемент | Действие |
| --- | --- |
| «К событиям ловушки» | Журнал с фильтром deployment ID |
| Endpoint / имя ловушки | Карточка развёртывания |
| «Ограничить источник» | Переключает на «Ответные действия»; немедленной блокировки нет |
| «Отчёт» | Страница отчёта сессии |
| «Плеер сессии» | Наблюдение и воспроизведение |
| «Ответные действия» | Ограничения источника для этой ловушки |
| «Дело и контекст» | Создание дела, конфигурация, технические сведения |

В шапке — IP, протокол, время начала, версия и hostname, число событий. «Окончание не получено» честно означает отсутствие доставленного события завершения: это не доказательство, что клиент всё ещё подключён. Старая сессия остаётся привязана к старой версии, даже если ловушка уже перезапущена.

Предупреждение о сборе показывает offline/revoked/degraded, потери и parser errors. Уже сохранённую историю можно читать при потере связи сенсора. Ошибка/неполная загрузка истории не скрывается; «Повторить» заново загружает её.

### 12.2. Каждая кнопка плеера

| Элемент | Что произойдёт |
| --- | --- |
| Значок паузы «Приостановить просмотр» в LIVE | Режим PAUSED: текущие строки удерживаются, новые данные накапливаются отдельно |

| `LIVE` / «Вернуться в LIVE» / «В LIVE · N новых» | Повторная загрузка недостающих данных и возврат к текущему состоянию |
| «Загружаем историю…» | Загрузка catch-up; повторное действие временно недоступно |

### 12.3. Что именно транслируется

SSH-плеер показывает connect/login, введённые команды `ssh.command`, сохранённые фрагменты ответа `ssh.output`, завершение и другие связанные события. Это записи Cowrie, не выполнение команд на управляющем компьютере. Ответы могут приходить фрагментами и включать приглашение/эхо команды; это не видеозапись экрана клиента.

Вывод отображается обычным текстом: опасные управляющие последовательности удаляются, HTML не исполняется. Запись ограничена квотой 256 KiB на SSH-канал, размером ожидающего буфера 64 KiB и фрагментами 16 KiB. При превышении появляется событие ошибки/усечения. Исторические сессии, созданные до добавления записи вывода, могут содержать только команды; интерфейс не должен дорисовывать им фиктивные ответы.

Одновременно в области плеера рисуется до 250 строк текущей части истории. Более ранние записи остаются доступны перемоткой; ограничение видимого окна не равно удалению серверной истории.

HTTP-плеер показывает запросы, попытки входа и обращения к файлам. Сессии HTTP связываются с анонимной cookie посетителя и IP; новый браузер/новая cookie может создать другую сессию. Это не отслеживание личности.

### 12.4. Правила и свидетельства

Правило содержит название, важность, объяснение, rule ID/version и конкретные evidence ID. Например, обращения к синтетическому файлу — наблюдаемое действие, а `wget` в эмулированной оболочке может показывать намерение загрузки. Оно не доказывает состоявшуюся сетевую передачу. Наличие отдельного сетевого события подтверждает только записанную активность/направление.

Если свидетельство не загрузилось, интерфейс сообщает об этом; отсутствие записи не заменяется выдуманной строкой. Цвет высокой важности — классификация правила, не вероятность успешного взлома.

### 12.5. «Дело и контекст»

«Создать дело» открывает форму с текущей сессией. «Все расследования» ведёт в «Дела». В «Точной конфигурации» раскрываются версия, hash и JSON; в техническом контексте — источник и идентификаторы истории. Эти блоки позволяют объяснить жюри, какой именно сервис видел посетитель.

## 13. Ограничение источника

Доступно в карточке ловушки и в сессии на «Ответные действия». **Это временная блокировка новых подключений источника к одной ловушке.** Она не изолирует целую машину из всей сети и не завершает уже открытый SSH-канал.

### 13.1. Создание

| Поле / кнопка | Что сделать / результат |
| --- | --- |
| «Заблокировать источник» | Открыть диалог |
| «IP источника» | В сессии зафиксирован; в карточке ловушки введи ранее наблюдавшийся IPv4 |
| «Срок ограничения» | 1 минута для демо, 5 минут, 15 минут или 1 час |
| «Причина» | Обязательное объяснение оператора, до 500 символов |
| Область действия | Проверь имя и endpoint именно нужной ловушки |
| «Отмена» / крестик | Закрыть без нового запроса |
| «Запросить ограничение» | API сохраняет желаемое правило; далее ждём подтверждение агента |

API разрешает правило для реально наблюдавшегося источника текущего запуска работающей ловушки. Loopback, multicast, link-local, неподходящий IPv4, адрес управления/сенсора и чужой/устаревший источник не должны приниматься. Новая заявка не означает, что пакет уже блокируется.

Агент сохраняет политику локально, применяет правило `NEW` к bridge выбранной ловушки, проверяет результат и отправляет ACK конкретной ревизии. Поэтому другой HTTP-сервис для того же источника продолжает работать, а управляющая панель остаётся доступной.

### 13.2. Список и состояния

В записи видны IP, причина, срок, автор, время, текущая и подтверждённая ревизии, время ACK и ошибка при наличии.

| Состояние API | Смысл |
| --- | --- |
| `pending` — «Ожидает применения» | Запрос сохранён; актуального подтверждения применения/снятия ещё нет |
| `applied` — «Подтверждено агентом» | Агент подтвердил применение актуальной ревизии, связь достаточно свежая |
| `cancelled` — «Отменено» | Отмена подтверждена снятием правила |
| `expired` — «Срок истёк» | Срок закончился и снятие подтверждено |
| `error` — «Ошибка применения» | Агент сообщил ошибку выполнения; не считать источник заблокированным |
| `unknown` — «Нет подтверждения» | Нет достаточного свежего подтверждения, в том числе при offline |
| `superseded` — «Запуск изменился» | Изменился запуск/желаемое состояние; старое правило более не относится к текущему runtime |

«Отменить ограничение» отправляет новую ревизию желаемого состояния. До ACK агентом отмена может оставаться ожидающей: «Ожидает подтверждения отмены». При истечении UI может показывать «Срок истёк, обновляем состояние» — это не самоподтверждение снятия.

TTL исполняется локально на сенсоре отдельным циклом: кратковременная потеря API не должна превращать временную блокировку в вечную. После восстановления агент отправляет результат. Если сам сенсор/агент выключен, немедленное выполнение новых действий обещать нельзя.

### 13.3. Правильная проверка на защите

1. Создай настоящую SSH-сессию и открой её в панели.
2. Запроси ограничение на одну минуту с причиной «Демонстрационная проверка».
3. Дождись подтверждения агента.
4. **Открой второе новое SSH-подключение**: оно должно не установиться/завершиться по таймауту.
5. С того же ноутбука открой HTTP-приманку на 18080: она должна оставаться доступной.
6. Отмени ограничение или дождись срока и подтверждения снятия.
7. Новое SSH-подключение снова должно открыться.

Продолжение старой открытой оболочки — ожидаемое поведение `NEW`, а не ошибка блокировки. Кнопку не следует представлять жюри как «полную изоляцию атакующей машины».

## 14. Дела и расследования

**Адрес:** `/cases`; выбранное дело — `/cases?case=<id>`. Пункт меню «Дела», заголовок страницы «Расследования».

### 14.1. Создание дела

| Элемент | Результат |
| --- | --- |
| «Создать дело» на странице или в сессии | Диалог «Новое расследование» |
| «Название дела» | Обязательно, до 120 символов |
| Список «Сессии · N из 20» | Отметить от одной до двадцати связанных сессий; в контексте сессии она уже выбрана |
| «Заметка оператора» | Свободный текст до 4000 символов |
| «Отмена» | Закрывает форму |
| «Создать дело» в диалоге | Создаёт серверную запись; без названия/сессий недоступно |
| «Открыть „…“» после успеха | Переход к созданному делу |

Неизвестные session ID отвергаются API. Дело не изменяет телеметрию и не назначает блокировку автоматически.

### 14.2. Просмотр и изменение

| Кнопка / поле | Что происходит |
| --- | --- |
| Карточка дела слева | Показывает название, статус, дату, количество сессий; выбирает дело справа |
| «Состояние дела» | «Новое», «В работе», «Закрыто» |
| «Заметка оператора» | Изменяет рабочую заметку |
| «Сохранить изменения» | Отправляет status/note и известную revision в API |
| «Загрузить актуальную версию» при конфликте | Загружает последнее серверное состояние; несохранённый текст нужно предварительно сохранить отдельно |
| Карточка связанной сессии | Открывает плеер |
| «Отчёт» рядом с сессией | Отчёт этой сессии |
| «История действий оператора» | Сохранённые события создания/изменения дела |

Если другой оператор уже изменил дело, старая revision получает конфликт. Интерфейс не должен молча перезаписать чужую заметку. Закрытие дела — состояние расследования, а не остановка ловушки. В текущем редакторе меняются статус и заметка; переименование и изменение набора сессий после создания отдельными кнопками не реализованы.

## 15. Отчёт, JSON, печать и контрольная сумма

**Адрес:** `/sessions/<id>/report`. **Назначение:** подготовить доказуемый разбор конкретной сессии.

| Действие | Результат |
| --- | --- |
| «К плееру сессии» | Возврат к расследованию |
| «JSON» | Скачивание полученного документа со всеми включёнными записями и hash |
| «Печать / PDF» | Системный диалог печати браузера; выбрать «Сохранить как PDF» и место сохранения |
| Ссылка на evidence в причине обнаружения | Прокрутка к событию в хронологии отчёта |
| «Содержимое события» | Раскрытие payload; не выполнение содержимого |
| «Повторить» при ошибке | Новый запрос отчёта |

Для PDF: нажми «Печать / PDF» → в диалоге браузера выбери PDF/«Сохранить как PDF» → проверь страницы → сохрани файл. На macOS вариант зависит от браузера/системного диалога. Кнопка не загружает PDF на сервер: файл создаёт браузер.

Отчёт включает:

- IP, протокол, endpoint, время начала/доставленного завершения и формирования отчёта;
- число событий, срабатываний, версию приманки, состояние сбора;
- неизменяемую конфигурацию сессии, config hash и generation;
- причины обнаружения, важность, rule ID/version, evidence;
- хронологию команд, выводов и прочих наблюдений с provenance и двумя временами;
- связанные ограничения источника с ACK/ревизией;
- связанные действия оператора;
- качество сбора, watermark, очередь, потери, ограничения полноты;
- SHA-256 документа.

Браузер проверяет hash по каноническому JSON без поля `sha256`: отсортированные ключи, UTF-8, без лишних пробелов. Результаты: «Проверяем контрольную сумму…», совпадает, не совпадает или проверка недоступна. Совпадение — подтверждение соответствия полученному содержимому. **Это не цифровая подпись и не независимая гарантия авторства данных.**

Выборка ограничена 5000 событиями и 200 связанными записями аудита; усечение явно отмечено. Отчёт живой сессии может измениться после новых событий. Для фиксации конкретного снимка скачай JSON/PDF с указанным временем. Экспорт сессии не равен экспорту всего дела из нескольких сессий.

## 16. Журнал оператора

**Адрес:** `/audit`. Только чтение, последние 200 записей.

| Элемент | Смысл / действие |
| --- | --- |
| «Время» | Время сохранённого действия |
| «Оператор» | Автор/агент действия |
| «Действие» | Публикация, запуск, остановка, отзыв, ограничение, изменение дела, экспорт и т. п. |
| Технический action под названием | Точное машинное имя для разбора |
| Ссылка ID объекта, где доступна | Переход к профилю, ловушке или хосту |
| «Запись сохранена» | Раскрывает details JSON |
| «Повторить» в ошибке | Перезагружает список |

Запрос и исполнение — разные действия. «Запрошена остановка» доказывает запрос оператора; готовность/остановка runtime требует результата агента. Аудит не является удаляемым списком браузера: записи хранятся в PostgreSQL. У нераспознанного действия может быть показано точное машинное имя — запись от этого не исчезает.

Записи дел также ведут к `/cases?case=…`. Машинные действия ограничений: `source.block.requested`, `source.block.cancelled`, `source.block.applied`, `source.block.released`, `source.block.error`; дел — `case.created` и `case.updated`. Сам просмотр отчёта не создаёт действие `report.generated`.

## 17. Что видит посетитель ловушки

### 17.1. Настоящий HTTP-портал

Посетитель открывает endpoint 18080/18081, видит выбранную легенду, форму username/password и синтетические ресурсы. ## 18. Полный практический проход

### 18.1. Создать свою HTTP-ловушку

1. Войти → «Хосты»: выбрать неотозванный хост `192.168.139.142`, убедиться в свежем heartbeat и поддержке HTTP.
2. «Профили» → «Создать профиль».
3. «Сервис»: название `Demo — Finance`, HTTP, сервис `Finance Operations`, hostname `finance-demo-05`.
4. «Дополнительные настройки»: выбрать «Консоль активов», banner `nginx`.
5. «Файлы»: добавить `/opt/decoy/backup-notes.txt`, текст `SYNTHETIC LAB DATA`.
6. «Ресурсы»: оставить 128 MB / 0,5 CPU / 64 PID.
7. «Опубликовать» → проверить → «Опубликовать версию».
8. В карточке профиля «Развернуть v1».
9. Название ловушки `Finance demo custom`, этот сенсор, свободный порт, например `18082`.
10. «Развернуть ловушку» → дождаться стадий и «Работает».
11. Открыть `http://192.168.139.142:18082`, выполнить пробный вход синтетическими данными.
12. Открыть `http://192.168.139.142:18082/opt/decoy/backup-notes.txt`.
13. В HoneyForge «События», выбрать свою ловушку, найти файл, открыть событие и сессию.

На фронтенде появятся события и правило. На бэкенде: агент → локальный outbox → пакет API → проверка ownership/generation → commit → ACK → SSE → обновление браузера. Если порт занят, выбери другой свободный; создание профиля/новой формы не освобождает порт.

### 18.2. Изменить версию и сохранить доказательства

1. Профиль → «Создать новую версию».
2. Изменить файл/hostname → опубликовать `v2`.
3. У существующей ловушки в «Повторное развёртывание» выбрать `v2` → «Применить повторно».
4. Дождаться подтверждённого запуска, повторить HTTP-запрос.
5. Старая сессия должна показывать `v1`, новая — `v2`; generation различается.
6. Создать дело из нужной сессии, оставить объяснение.
7. Открыть «Отчёт», проверить hash, скачать JSON/PDF.
8. На своей ловушке «Остановить» → подтвердить → дождаться «Остановлена».

Этот проход показывает не только интерфейс, но и сохранение версии, защиту от устаревших результатов, исполнение агентом и происхождение наблюдений.

## 19. Демонстрация за три минуты

До выхода к жюри: открыть главную, проверить три LIVE-ловушки и сенсор, снять ненужные ограничения, сбросить фильтры; подготовить терминал с командой SSH. Удобно расположить браузер и терминал рядом. Создание профиля заранее экономит время.

| Время | Что нажимать / делать | Что объяснить |
| --- | --- | --- |
| 0:00–0:20 | «Сеть ловушек», показать карту и работающий сенсор | «Управление отделено от атакуемых сервисов; состояния подтверждает агент» |
| 0:20–0:50 | Подключиться к 2222, `whoami`, `hostname` | «Это правдоподобная SSH-приманка, а не настоящая рабочая машина» |
| 0:50–1:20 | Открыть новую сессию на карте/в ловушке, ввести `cat` синтетического файла | «Команда и ответ приходят в живой плеер; у записи есть ID и источник» |
| 1:20–1:40 | Пауза → ещё одна команда → «В LIVE · N новых»; нажать правило/evidence | «Сбор продолжается, просмотр управляемый, объяснение связано с доказательством» |
| 1:40–2:15 | «Ограничить источник» → запрос на минуту → дождаться ACK → новое SSH-подключение | «Блокируются новые подключения этого IP только к этой ловушке» |
| 2:15–2:30 | Открыть HTTP-приманку с того же ноутбука | «Область действия ограничена: другой сервис остаётся доступным» |
| 2:30–3:00 | «Дело и контекст» → создать дело; «Отчёт» → hash/JSON/PDF | «Сохраняем ход расследования, точную версию и отчёт; продукт работает без нейросети» |

Не показывай пароль оператора, ключ агента, полный `.env` или реальные личные данные. Если живой канал временно недоступен, открой **ранее сохранённую настоящую сессию** и честно назови её исторической. Не выдавай replay за текущую атаку.

## 20. Состояния, ошибки и восстановление

### 20.1. Состояния ловушки

| Состояние | Как понимать | Следующий шаг |
| --- | --- | --- |
| «В очереди» | Запрос сохранён, агент ещё не начал | Проверить heartbeat/подождать |
| «Применяется» | Задание исполняется | Смотреть стадии |
| «Работает» | Есть подтверждённый запуск | Открыть endpoint и получить реальное наблюдение |
| «Останавливается» | Остановка запрошена | Дождаться результата |
| «Остановлена» | Остановка подтверждена | При необходимости «Применить повторно» |
| «Ошибка» | Выполнение не удалось | Прочитать job/runtime error, устранить причину |
| «Неизвестно» | Свежего подтверждения недостаточно | Проверить сенсор; это не равнозначно остановке |

### 20.2. Типовые проблемы

| Симптом | Где смотреть | Что делать |
| --- | --- | --- |
| 5173 не открывается | Терминал панели | Запустить Vite из `apps/web`; проверить фактический порт |
| 8100 не готов | `/health/ready`, терминал API, PostgreSQL | Поднять базу, проверить миграции, запустить API |
| Ошибка входа | Форма входа, `access.txt` | Правильная учётная запись; не использовать SSH-пароль |
| Браузер потерял связь | Сообщение в шапке | Проверить API/сеть, дать SSE переподключиться |
| Сенсор «Не в сети» | «Хосты», OrbStack | Включить VM и проверить службу агента |
| Хост «Отозван» | Карточка хоста | Новая регистрация, а не повтор старого токена/ключа |
| Нет совместимого хоста | Форма развёртывания | Выбранный адаптер поддерживается и heartbeat свежий |
| Порт занят | Ошибка формы/задания | Выбрать свободный; не завершать посторонние процессы |
| Контейнер не готов | Стадии и error ловушки | Проверить образ, ресурсы, порт и изоляцию |
| Нет событий | Фильтры, пауза, очередь | Подключаться к endpoint сенсора, снять лишние фильтры, проверить доставку |
| Ответы SSH не видны в старой истории | Provenance/тип событий, предупреждение | Старый runtime мог не записывать output; создать новое реальное подключение после обновления |
| Нет завершения сессии | Очередь/heartbeat | Подождать disconnect; не считать отсутствие завершения живым подключением |
| Блокировка «ожидает» | Ревизия/ACK, хост | Проверить связь и ошибку агента; не объявлять успешной заранее |
| Старый SSH продолжает работать после блока | Область действия политики | Проверять новое подключение: установленные каналы сохраняются |
| Истёк TTL, но статус неизвестен | ACK/heartbeat | Локальное снятие и серверное подтверждение различаются; дождаться связи |
| Конфликт дела | Сообщение о revision | Скопировать свой текст отдельно, загрузить актуальную версию, повторить нужные изменения |
| Hash не совпадает | Раздел целостности отчёта | Перезагрузить отчёт, не заявлять проверенную целостность до совпадения |
| JSON/PDF не скачался | Диалог/загрузки браузера | Разрешить загрузку, выбрать путь/назначение печати |

Для текущей VM проверить/перезапустить агент можно из отдельной вкладки:

```sh
/Applications/OrbStack.app/Contents/MacOS/bin/orbctl run -m honeyforge-sensor -u root systemctl status honeyforge-agent
/Applications/OrbStack.app/Contents/MacOS/bin/orbctl run -m honeyforge-sensor -u root systemctl restart honeyforge-agent
```

Перезапуск службы не удаляет локальный outbox. Если агент не может подтвердить базовую изоляцию, он останавливает свои управляемые ловушки; сначала восстанови правила/службу, затем явно проверь и запусти нужные ловушки.

### 20.3. Проверка потери связи до защиты

Проверочный сценарий `uv run python scripts/verify-live-lab.py --offline` использует отдельные временные HTTP/SSH-развёртывания на 18280/12222. Он реально ограничивает связь сенсора с API примерно на минуту, проверяет локальную очередь, TTL, восстановление и отсутствие дублей. Панель управления при этом остаётся доступной. Сценарий временно влияет на доставку всех событий этого сенсора, поэтому запускай его до демонстрации; это не повседневная кнопка панели.

После проверки созданные тестовые ловушки останавливаются, история остаётся. Результат сохраняется в [live-lab.json](evidence/backend/live-lab.json). Для чистого начала расследования создавай новую сессию: общего интерфейсного «стереть всю историю» нет.

## 21. Архитектура: что и почему сделано

| Решение | Как устроено | Почему полезно и как объяснить жюри |
| --- | --- | --- |
| Разделение управления и сенсора | React/API/PostgreSQL отдельно от Linux VM с приманками | Компрометация/нагрузка приманки не должна давать прямой доступ к управляющей базе |
| Модульное приложение API | Схемы/сервисы приложения, инфраструктура, HTTP-слой | Бизнес-правила тестируются отдельно от интерфейса и Docker; без лишней сложности микросервисов |
| Неизменяемые версии | Новая конфигурация — новая версия + hash | Можно воспроизвести, что видел источник конкретной сессии |
| Desired/observed state | Запрос оператора отделён от отчёта агента | Нажатая кнопка не выдаётся за выполненное действие |
| Задания с арендой, attempt/revision | Агент забирает задание, обновляет прогресс, возвращает fenced result | Потеря связи и поздний ответ не должны ломать более новый запуск |
| Идемпотентность | Повтор запроса с тем же ключом и телом возвращает тот же результат | Повтор при сетевой ошибке не создаёт дубликат развёртывания/политики |
| Локальный SQLite outbox | Событие и курсор сохраняются атомарно, WAL/FULL; доставка с повторами | Краткий offline не должен стирать ещё не доставленные наблюдения |
| Дедупликация + ACK после commit | Event ID уникален, подтверждение после сохранения | Повторная доставка не превращает одно событие в несколько |
| Отдельный поток сбора | Сбор логов/пакетов не ждёт сетевого запроса к API | Offline API не блокирует локальную запись |
| Snapshot + watermark + SSE | История загружается страницами, поток сообщает об изменениях, курсор помогает восстановиться | LIVE, пауза и догрузка работают поверх сохранённых данных |
| Детальные provenance/time/generation | Источник, два времени, точное поколение и версия | Видны задержки и происхождение; старые события не приписываются новой конфигурации |
| Детерминированные правила | Версия правила, объяснение, evidence ID | Выводы проверяемы, нейросеть не нужна |
| Ограничение на bridge и `NEW` | Только новые соединения IP к выбранной ловушке | Панель/другие приманки остаются доступны; честно ограниченная область действия |
| Локальный TTL и ACK | Правило переживает перезапуск, срок проверяется на сенсоре, результат сообщается серверу | Временное правило не зависит только от доступности API |
| Optimistic concurrency дел | Изменение с известной revision | Два оператора не перезаписывают друг друга молча |
| Ограниченные буферы и проекции | Квоты outbox/вывода, лимиты выборки, counters/предупреждения | Ресурсы предсказуемы, неполнота не скрывается |
| Cookie/CSRF и индивидуальные ключи | Раздельные сессии оператора и агента | Ключ одной машины не является общим паролем всей системы |
| SHA-256 отчёта | Сервер формирует документ, браузер перепроверяет содержимое | Можно обнаружить изменение экспортируемого документа; не подменяет подпись |

Более подробные альтернативы и компромиссы: [ARCHITECTURE.md](ARCHITECTURE.md), [DECISIONS.md](DECISIONS.md). UI-референсы Mobbin и связь с экранами: [UI_REFERENCES.md](UI_REFERENCES.md). Принципы интерфейса: обзор → конкретное наблюдение → свидетельство → действие; настройки приманки рядом с предпросмотром; подтверждения и ошибки доступны оператору.

### 21.1. Что происходит на фронтенде и бэкенде по каждому экрану

Названия маршрутов ниже нужны для технических вопросов на защите. Все `/api/v1` защищены операторской сессией; изменяющие действия дополнительно проверяют CSRF. Внутренний `/agent/v1` использует индивидуальный ключ агента, кроме одноразовой регистрации. Живые сенсоры обращаются по HTTPS к отдельному gateway через `/assets/sync/v1`; внутренние маршруты и Swagger снаружи закрыты.

| Экран / действие | Фронтенд | Бэкенд / агент |
| --- | --- | --- |
| Вход, выход, восстановление сессии | Форма и очистка приватного кэша | `auth/login`, `auth/logout`, `auth/me`; проверка пароля/сессии |
| Главная | Загружает сводку, карту, rules; обновляет после SSE и по интервалу | GET `overview`, `topology`, `findings`; проекции сохранённых данных |
| Хосты | Таблица, выбранный хост, токен/отзыв в диалоге | GET `hosts`, POST `hosts/enrollment-tokens`, `hosts/{id}/revoke`; агент POST `enroll`/`heartbeat` |
| Каталог и карточка профиля | Загрузка, выбор версии, переход к редактору/запуску | GET `profiles`, `profiles/{id}`; история версий |
| Конструктор и preview | Локальный черновик/валидация/предпросмотр | При публикации POST `profiles` или `profiles/{id}/versions`; проверка, hash, audit |
| Многосервисная группа | Конструктор v3, все протоколы/порты, общий и индивидуальные статусы | GET/POST `deployment-groups`, GET `deployment-groups/{id}`, POST `stop`/`redeploy`; одна группа и отдельные задания сервисов |
| Geo/ASN | Раскрываемый блок с фактической доступностью, провайдером/датой и private/unavailable | GET `geo-sources`; локальные базы DB-IP City/ASN Lite, без подставных событий |
| Новая ловушка | Выбор profile/version/host/port, idempotency key, переход к карточке | POST `deployments`; желаемое состояние и durable job |
| Карточка, остановка, redeploy | Показывает стадии/результат; отправляет stop/redeploy | GET `deployments/{id}`, POST `stop`/`redeploy`; агент `jobs/claim`, `progress`, `result`, `runtimes` |
| События и подробности | Фильтры в URL, таблица, удержание просмотра | GET `events`; фильтр/пагинация сохранённых записей |
| Экспорт событий | Скачивает полученный JSON | POST `exports`; ограниченный canonical export + audit |
| Сессия | Загружает сведения и все страницы playback, сохраняет состояние просмотра | GET `sessions/{id}`, `sessions/{id}/playback`; watermark/позиции |
| LIVE / пауза / replay | SSE инициирует догрузку; пауза и replay управляют показом на клиенте | GET `stream`; история в БД; сбор агентом не выключается |
| Ограничение / отмена | Показывает только фактический status/ACK, ошибки и срок | GET/POST `source-blocks`, POST `source-blocks/{id}/cancel`; агент GET `source-policies`, POST policy `ack` |
| Дело | Список/выбор сессий, note/status, конфликт | GET/POST `cases`, POST `cases/{id}` с revision; audit |
| Отчёт | Показывает полученный документ, проверяет hash, скачивает/печатает | GET `sessions/{id}/report`; snapshot конкретной сессии/версии/evidence |
| Журнал оператора | Таблица, ссылки объектов, раскрытие JSON | GET `audit`; последние сохранённые действия |

Чтение таблицы, раскрытие JSON, поиск в редакторе, перемотка и печать не запускают контейнер и не меняют телеметрию. Серверные изменения выполняются явными публикациями/командами; подтверждённый результат агента появляется отдельно.

## 22. Границы реализации и доказательства

Что можно заявлять: реальные HTTP/SSH-взаимодействия на отдельной Linux VM, получение телеметрии, запись SSH-команд/ответов нового runtime, сохранённая история, правила с evidence, управляемый плеер, версии, задания, точечные ограничения с ACK/TTL, дела и отчёт. Доказательства и даты: [BACKEND_STATUS.md](BACKEND_STATUS.md), [FRONTEND_STATUS.md](FRONTEND_STATUS.md), [ACCEPTANCE.md](evidence/frontend/ACCEPTANCE.md), [live-lab.json](evidence/backend/live-lab.json).

Чего нельзя обещать по этим проверкам:

- Победу на хакатоне: критерии и состав жюри неизвестны.
- Полную изоляцию атакующей машины или завершение открытого SSH-подключения одной кнопкой ограничения.
- Определение реальной ОС/личности посетителя по эмулятору и IP.
- Успешную загрузку вредоносного файла только по `wget/curl` в Cowrie.
- Захват всего содержимого сетевых пакетов: текущий сетевой сбор фиксирует ограниченные метаданные IPv4, не полноценный PCAP.
- Бесконечный объём вывода/событий: квоты и усечение имеют наблюдаемые признаки.
- Произвольные протоколы, multi-tenant RBAC, SIEM/SOAR-интеграции и облачную эксплуатацию, которых здесь нет.
- Производительность и надёжность внешнего размещения по проверке одного локального стенда.

Записи журнала разработки: [WORKLOG.md](WORKLOG.md) и [WORKLOG-FRONTEND.md](WORKLOG-FRONTEND.md). Для защиты используй проверенные действия, отдельно называй ограничения и отличай запрос от подтверждённого исполнения.


## Обновление v2: архив, закрытые наблюдения и хранение

Подробное описание текущих новых кнопок находится в UI_OPERATIONS_V2.md. Конструктор
новых профилей публикует schema v2. Старые версии остаются читаемыми и сохраняют hash.
Рекомендуемый порт профиля не меняет фактический порт запущенной ловушки.
Учётки-приманки относятся только к эмулируемому сервису.

В HTTP v2 правильная фиктивная пара открывает пустой синтетический workspace, неверная
даёт 401. В SSH v2 проверяется указанная пара. У Cowrie v2 есть явный предел сеанса
30 минут, у v1 сохранён прежний предел 5 минут. Это не бесконечный shell.

Пароль/payload наблюдения сохраняются отдельно в encrypted capture. Явное раскрытие
разрешено admin/operator/analyst, viewer получает отказ. Сервер пишет аудит и no-store.
PCAP является отдельным приватным файлом и может содержать raw HTTP plaintext.
Закреплённое дело сохраняет связанные доказательства от автоматического retention.
Если удаление уже началось, pin возвращает409 и требует обновить состояние.


## Дополнение: уникальные маркеры, алерты, Geo и сертификаты

Актуальные названия каждой кнопки и разрешения перечислены в UI_OPERATIONS_V2.md,
включая бонусные операции. Короткая последовательность:

1. В карточке профиля открыть раздел уникальных приманок, выбрать опубликованную версию,
   выпустить URL для HTTP либо файл для HTTP/SSH. В этой версии допускается до восьми
   активных маркеров. Выпуск не изменяет неизменяемую конфигурацию и действующие ловушки.
2. Выполнить явное переразвёртывание подходящей ловушки. Каждый запуск получает отдельный
   случайный marker и binding. Открыть URL или прочитать файл в настоящем SSH; реестр
   показывает использование, а finding связан с наблюдаемым событием/run. Одна команда
   `cat` без наблюдаемого маркера не доказывает чтение.
3. Отзыв прекращает attribution новых обращений сразу. Старые байты сохраняются до явного
   redeploy. Наблюдения до момента отзыва, доставленные позже из outbox, сохраняются.
4. В журнале раскрыть настройки повторных входов. Порог/период/enabled изменяют только
   admin/operator после review. Revision защищает от перезаписи изменения другого окна.
   Считаются фиксированные окна observed_at. Историческое опоздавшее выявление не выдаётся
   за новый LIVE всплеск. Viewer/analyst могут читать настройку, но не менять её.
5. В журнале/отчёте выбрать IoC CSV или STIX. Фильтры и session scope сохраняются. Экспорт
   содержит наблюдаемые адреса, available-file hash и исходные event/deployment/generation
   IDs/provenance, до 5000 событий с явным усечением. Это STIX Observed Data, не утверждение
   о вредоносности IP. Viewer не экспортирует. Export не содержит private credentials.
6. Geo/ASN отображает приближённые сведения локальных баз и дату их сборки. Без City/ASN
   MMDB, для частных IP и отсутствующих записей показана недоступность. IP/местоположение
   не являются личностью человека. На стенде подключены DB-IP City/ASN Lite выпуска 2026-10;
   их доступность, провайдер, дата сборки и возраст проверены в живом UI на 390/1280.
   Частные IP остаются недоступными для геолокации. Ссылка DB-IP и CC BY 4.0 видны на экране.
7. В карточке хоста admin читает публичные сертификаты и отзывает выбранный после review.
   Активный сертификат, overlap и revoked/expired различаются. Ключ находится только на
   сенсоре. Через CLI можно запросить ротацию; service подтверждает новый TLS-клиент и
   оставляет старый на 300 секунд. При отзыве всех сертификатов необходима новая
   регистрация оператора, прежнее приватное состояние не удаляется. Отзыв host identity —
   отдельная операция: она прекращает управление этой identity и останавливает её ловушки.

Стандартная SSH легенда v2 согласует Ubuntu banner, uname/os-release и hostname.
Произвольная замена banner требует собственного согласования легенды. Эмулятор не
является настоящей гостевой ОС. Structured login/payload шифруются до вывода в журналы;
произвольный shell output и binary PCAP — отдельные приватные доказательства, не обещание
шифрования всех байтов. Отключение записи введённых credentials отключает соответствующую
закрытую HTTP-запись целиком, чтобы исходное тело не сохраняло пароль через другой параметр.
