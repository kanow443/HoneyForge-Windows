# HoneyForge

Материалы команды **Uni**: [подробное описание проекта](deliverables/Uni-HoneyForge-project-guide.md), [презентация защиты](deliverables/Uni-HoneyForge-defense.pptx), [вопросы и ответы](deliverables/Uni-HoneyForge-questions.md). В дополнение к четырём операторским ролям реализована изолированная роль участника CTF, зачёт флагов из активных honeytokens и аудируемые пометки событий. Для установки новой схемы требуется миграция `014`.

HoneyForge — центр управления ловушками для наблюдения за подозрительной активностью. Оператор создаёт правдоподобный профиль, развёртывает его на удалённом хосте и получает события, состояние ловушки и историю сессий в одной панели.

Реализованы профили v2 с совместимостью v1, настоящий Low TCP, Medium HTTP/SSH, шифрование credentials до журналов и очереди, LIVE/replay-плеер, PCAP и SFTP-файлы, подтверждённая SSH-реакция, роли, дела, закрепление доказательств, retention и интеграции. Реальные агенты работают через отдельный HTTPS management gateway и сеть управления. Есть проверенное независимое восстановление базы, файлов и ключей. Текущее состояние и границы проверок описаны в [backend status](docs/BACKEND_STATUS.md) и [frontend status](docs/FRONTEND_STATUS.md). Качественные критерии известны из полного ТЗ; веса, состав жюри и дедлайн не объявлены. Продукт не использует нейросети или AI API.

Для Windows: [пошаговая установка и запуск](README_WINDOWS.md), вход — `START_WINDOWS.cmd`.

## Основное решение

React и TypeScript для панели; FastAPI и PostgreSQL для управления и данных; отдельный Python-агент на Linux-хосте; Docker для HTTP-приманки и SSH-эмуляции Cowrie. Управление и атакуемые сервисы находятся в разных виртуальных машинах. События сохраняются перед отправкой, сервер удаляет повторы, браузер получает обновления через SSE.

Следующие этапы и критерии приёмки находятся в [концепции развития](docs/PRODUCT_CONCEPT.md). Исходный [план поставки](docs/DELIVERY_PLAN.md) сохраняет задачи базовой реализации. Каждый этап заканчивается работающим результатом, проверкой и записью в журнале.


Завершены дополнительные сервисы: уникальные URL/файлы honeytokens, настраиваемые
наблюдаемые окна failed-login, IoC CSV/STIX 2.1 Observed Data, локальный MMDB reader,
согласованная стандартная persona и индивидуальная mTLS ротация. Реальные доказательства:
`docs/evidence/backend/bonuses.json`, `certificates.json`, `client-tls.json` и
`docs/evidence/frontend/bonus-browser-acceptance.json`. Оригинальные City/ASN DB-IP Lite release 2026-10 теперь подключены и включены в Windows
комплект с CC BY 4.0 attribution; обновление — `START_WINDOWS.cmd -Action Geo`.
Профиль v3 объединяет 2–8 сервисов/портов, панель управляет общей группой.
Маскировка дополнена padding, задержками и SPKI pinning. Поддерживаются Low
(TCP-баннер) и Medium (HTTP/SSH). Актуальные проверки: [REQUIREMENTS.md](docs/REQUIREMENTS.md).
Старые нагрузочные evidence сохраняют свои исходные условия.
